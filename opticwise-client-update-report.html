1. CRM: Contacts and Companies Rebuild Complete

Full replacement of legacy Pipedrive data with a clean, email-derived contact database
The Problem
  • The CRM was populated with Pipedrive data that contained many entries that were not real business contacts
  • Contacts were not properly linked to companies or deals
  • No reliable way to distinguish actual business relationships from one-off email interactions
What We Built
  • Email-based contact extraction engine -- scans all sent email history and identifies real contacts based on outbound engagement, not just replies
  • Tiered qualification logic -- contacts are scored by initiation frequency, thread depth, and recency to separate active relationships from noise
  • Signature parsing -- automatically extracts name, title, company, phone, and other profile data from email signatures
  • Multi-user extraction -- system supports scanning any user's email, not just one account
  • Full CRM refresh pipeline -- single command to clean, extract, deduplicate, and replace the entire contact database

2. Admin Controls and User Self-Sync Live

Team member management, email sync configuration, and per-user privacy enforcement
Admin Panel (Settings Page)
  • Create and manage team users -- admins can add new users with name, email, department, and role
  • Edit user profiles -- update name, email address, and department for any team member
  • Password reset -- admin can reset passwords for team members directly
  • Department assignment -- users can be tagged by department (finance, marketing, ops) for future permission controls
Email Sync: Self-Service Activation
  • Each user has an Email Sync Enabled toggle that can be activated per user
  • Once enabled, that user's Gmail is synced automatically via a cron job running every 15 minutes on Render
  • Users see only their own email threads -- strict per-user privacy isolation enforced at the database query level
  • Sync status is tracked per user: last sync time, sync status (ok / error / syncing)
  • Google service account credentials are configured on Render so new users can be onboarded without additional credential setup
Privacy Enforcement
Per-user email privacy was implemented across the entire platform. Every query that touches email threads, contacts, or AI search results filters by the logged-in user. Users cannot see each other's email data, contacts extracted from their emails, or AI agent results sourced from another user's messages.

4. Knowledge Base: Document Upload and Vectorization Live

Upload documents into the platform for AI-powered search, retrieval, and agent responses
What It Does
  • Upload PDFs, Word documents (.docx), and plain text files directly into the OWnet platform
  • Documents are automatically parsed, split into chunks, and vectorized for semantic search
  • The AI agent (OWnet chat) searches the knowledge base on every query and cites uploaded documents in its responses
  • Documents can be categorized (Proposals, Contracts, Technical Docs, Research, Marketing, Financial, Training, Policies, and more)
Use Cases This Enables
This is the system for handling tasks such as uploading the PPP book content as well as importing OW market research information. Any document uploaded here becomes immediately searchable and available to the AI agent for answering questions, generating summaries, and referencing in conversations.
  • PPP Book -- upload the full book content and the AI agent can answer questions about it, summarize sections, and reference specific passages
  • Market research -- upload industry reports, competitive analysis, or market data and query it conversationally
  • Proposals and contracts -- store and search across deal-related documents
  • Training materials -- onboard new team members by making internal docs queryable via the AI agent
  • Any reference material -- technical specs, playbooks, policies, or any document the team needs quick access to
Technical Details
  • Drag-and-drop upload interface with progress tracking
  • Text extraction via pdf-parse (PDFs) and mammoth (Word documents)
  • Content is chunked into searchable segments and vectorized using OpenAI embeddings
  • Stored in the platform database with full CRUD management (list, rename, re-categorize, delete)
  • AI agent performs vector similarity search across all uploaded documents on every conversation
  • Source citations displayed in agent responses so users can see which document the information came from

6. Slack Bot Integration Live

Access the full OWnet AI agent directly from Slack -- same capabilities as the web interface
What It Does
  • Mention @ownet in any Slack channel or send a direct message to get AI-powered answers from the full OWnet agent
  • Same AI quality, data access, and source citations as the web interface -- CRM data, emails, transcripts, knowledge base, and all connected sources
  • Thread-based conversations maintain context, so follow-up questions work naturally
  • Deep analysis mode supported (e.g., "Deep analysis of all customer activity")
How It Works
  • @ownet mentions -- tag the bot in any channel and ask a question
  • Direct messages -- message the bot privately for individual queries
  • Threaded replies -- the bot responds in-thread to keep channels clean and maintain conversation context
  • Progress indicators -- emoji reactions show when the bot is processing (eyes) and when it completes (checkmark)
  • Long responses -- if a response exceeds Slack's message limit, the full answer is uploaded as a file attachment
  • Rich formatting -- responses use Slack blocks for clean, structured display of data and citations
Recent Fixes (Mar 2)
Resolved a series of issues preventing the Slack bot from functioning end-to-end. Fixed authentication so the bot can communicate with the platform securely without user-level session tokens. Resolved database table initialization, foreign key errors, and internal port mismatches. The bot is now fully operational -- it receives mentions, queries the OWnet agent, and posts responses back to Slack threads.
  • Internal API key auth bypass -- bot communicates with OWnet API using AUTH_SECRET instead of session tokens
  • Auto-create database tables -- SlackUser, SlackSession, and SlackMessageLog tables are initialized on first use
  • Service user for sessions -- bot creates a dedicated service user to satisfy AgentChatSession foreign key constraints
  • Correct PORT binding -- fixed internal API call from port 3000 to the correct Render port 10000
  • Table init endpoint -- added /api/slack/init-tables endpoint for manual table creation
  • Reaction scope handling -- graceful fallback when reactions:write scope is missing from Slack app config
  • Comprehensive logging -- detailed diagnostics added throughout the Slack event pipeline for monitoring
Technical Architecture
  • Slack Events API webhook endpoint with signature verification and replay attack prevention
  • Slack user-to-OWnet user mapping stored in the database (SlackUser, SlackSession, SlackMessageLog tables)
  • Internal API key authentication using AUTH_SECRET for secure server-to-server calls
  • Streaming response handling -- reads the OWnet agent's streamed response and assembles the full answer before posting to Slack
  • Built with @slack/bolt and @slack/web-api SDKs
